# GAIA · Grow / Global / Ocean

Система мониторинга участков и окружающей среды: реальные показания приборов, спутниковые карты, климатические ряды, анализ территорий и водных экосистем. Стек: FastAPI, SQLAlchemy/Alembic, React, Leaflet, Recharts; SQLite или PostgreSQL.

**Начните с [полной инструкции по запуску и подключениям](docs/real-data-setup.md).** [Источники и методы](docs/earth-data-methods.md) · [Обучение моделей](docs/model-training.md) · [Проверки и ограничения](docs/earth-verification.md).

## Запуск существующего проекта

Нужны Python 3.13+ и Node.js 24+. В PowerShell:

```powershell
cd D:\GAIA
notepad .env
```

Сначала заполните `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM`. При регистрации и каждом новом входе нужен шестизначный код из письма. Без настроенной отправки писем вход завершить нельзя. Настройки Gmail и других сервисов описаны в [инструкции](docs/real-data-setup.md).

```powershell
.\scripts\dev.ps1 -UseSqlite
```

Откройте [GAIA](http://localhost:5173). Остановка обоих приложений — **Ctrl+C в том же терминале**. После редактирования `.env` перезапустите проект.

Существующая локальная база: `data/gaia.db`. В ней главный администратор **SENQwir**, email **gulnarapulatova9@gmail.com**, пароль сохранён. `-UseSqlite` выбирает именно эту базу; PostgreSQL из `.env` содержит отдельные аккаунты. Новая база сама по себе не содержит существующий пароль.

Не перезаписывайте существующий `.env` примером. Для нового checkout создайте `.env` из `.env.example`, затем настройте подключения. Все API-ключи остаются на сервере; переменные `VITE_*` для них не используются.

## Разделы

- **Grow** — участки, зоны, растения, реальные устройства и телеметрия, полевые заметки, внешние погодные/атмосферные данные, спутниковая карта, экспорт и помощник.
- **Global** — административная обсерватория: Земля, глобальные температура и CO₂, полярный лёд, временные спутниковые слои, анализ выбранных областей, история, природные события и справочник организаций.
- **Ocean** — морские условия, хлорофилл на картах NASA, спектральные водные индикаторы Sentinel‑2, архив площади воды JRC и исследовательская модель риска микропластика.
- **Доступ** — главный администратор выбирает администраторов среди зарегистрированных пользователей. Доступ проверяется сервером; обычные пользователи работают со своими участками Grow.

Рабочие экраны исключают старые сгенерированные данные; фоновая генерация и виртуальный полив отключены. История остаётся в базе. Расчётные продукты CAMS/Open-Meteo обозначены как модели, а не полевые измерения.

## Подключения

| Возможность | Настройка в `.env` |
|---|---|
| Подтверждение email | `SMTP_*` — требуется для входа |
| Текстовый помощник, распознавание и озвучивание | `OPENAI_API_KEY`, модели `OPENAI_*` |
| Расчёт индексов и изображение области Sentinel‑2 | `COPERNICUS_CLIENT_ID`, `COPERNICUS_CLIENT_SECRET` |
| Earth Engine: лесной покров и водная поверхность | `GEE_PROJECT`, `GEE_SERVICE_ACCOUNT`, `GEE_KEY_FILE` |
| NASA Earthdata, дополнительные права каталога | `EARTHDATA_TOKEN` — необязателен для открытых продуктов |
| Точки тепловых аномалий FIRMS | `FIRMS_MAP_KEY` |
| Коммерческий Open-Meteo | `OPENMETEO_API_KEY` |

GIBS, EONET, открытые CMR/STAC, GISTEMP, NOAA CO₂ и NSIDC используются без ключей. Подробные действия и условия доступа — в [руководстве](docs/real-data-setup.md). Наличие ключа в настройках не гарантирует права или достаточную квоту провайдера.

## Обучение экологических моделей

Готов процесс обучения Random Forest и безопасный JSON-формат выполнения моделей риска суши и микропластика. Реальные размеченные данные необходимо собрать; научно проверенные веса не поставляются. [Инструкция](docs/model-training.md) включает шаблоны, единицы, разделение площадок и дат, команды обучения и оценку ошибок.

Мутность в NTU, концентрация микропластика, токсичность цветения и общий балл здоровья планеты не выводятся из неподтверждённых формул. Границы каждого продукта описаны в [методике](docs/earth-data-methods.md).

## Проверка

```powershell
cd D:\GAIA
$env:DATABASE_URL = "sqlite:///D:/GAIA/data/gaia.db"
.\scripts\check.ps1
.\.venv\Scripts\python.exe scripts/probe_earth_sources.py
cd apps\web
npm run test:e2e
```

Unit-тесты используют временную БД. Браузерные проверки используют `data/gaia_e2e.db`, тестовую доставку кодов и запись ответов открытых API; в рабочем сервере таких переключателей нет. Проверка живых источников выполняется отдельно.

Перед обновлением другой существующей SQLite-базы остановите API и выполните `scripts/upgrade_sqlite.py` с правильным `DATABASE_URL`. Скрипт создаёт резервную копию и проверяет сохранность старых строк перед обновлением основной базы. Локальная база этого проекта уже обновлена до `b125a48e930f`.

Документация прежнего этапа сохранена как [архив](docs/legacy-readme.md); старые сценарии виртуальных устройств не относятся к текущему рабочему режиму.

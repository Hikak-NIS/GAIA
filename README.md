# GAIA

Реализован Phase 1: зоны, профили и экземпляры растений, реестр устройств и раздельные REAL/SIMULATED данные. [Инструкция пользователя](docs/phase1-guide.md) · [Архитектура и план по файлам](docs/phase1-plan.md).

Перед миграцией существующей SQLite базы остановите API и выполните `.venv\Scripts\python.exe scripts/upgrade_sqlite.py`. Скрипт создаёт резервную копию, проверяет обновление копии и сохранность каждой старой строки, затем обновляет рабочую базу.


Рабочий MVP наблюдения за небольшим участком и безопасного управления виртуальным поливом. Интерфейс на русском; серверная авторизация, данные и решения сохраняются в БД. Реальный Raspberry Pi сможет отправлять ту же модель телеметрии, которую использует симулятор.

## Запуск через Docker Compose

Требуются Docker Desktop и Compose.

PowerShell:

```powershell
Copy-Item .env.example .env
docker compose up --build
```

Bash:

```bash
cp .env.example .env
docker compose up --build
```

Frontend: http://localhost:5173  
Backend: http://localhost:8000  
OpenAPI: http://localhost:8000/docs

PostgreSQL — основной режим. Compose ждёт readiness БД, применяет Alembic и запускает один API worker, чтобы фоновые ticks не дублировались.

## Быстрый запуск без Docker

Для локальной демонстрации можно использовать SQLite. Нужны Python 3.13+ и Node.js 24+.

PowerShell:

```powershell
.\scripts\dev.ps1 -UseSqlite
```

Bash:

```bash
chmod +x scripts/dev.sh
./scripts/dev.sh --sqlite
```

Остановите `Ctrl+C`. Скрипт создаёт `.venv`, устанавливает зафиксированные зависимости, применяет миграции и запускает оба приложения. Секретов в репозитории нет; `.env` исключён из Git.

## Демонстрация «засуха → восстановление»

1. Откройте сайт, зарегистрируйтесь и создайте «Мой двор». Точку можно выбрать на карте.
2. Откройте «Симуляция», выберите «Засуха», скорость ×60 и нажмите «Запустить».
3. Во вкладке «Полив» выберите автоматический режим, порог 30%, цель 45% и сохраните правила.
4. Примерно через несколько секунд влажность станет ниже 30%. Появятся предупреждение и запись «Автополив включён» с причиной.
5. Виртуальный насос повысит влажность и уменьшит резервуар, после цели автоматически остановится. В истории будут длительность, причина и расход.
6. Добавьте наблюдение, откройте карту, погоду, предупреждения и сформируйте ежедневный отчёт.
7. Выйдите и войдите снова: территория, история и наблюдения сохранятся.

Все управляющие элементы относятся только к симуляции. `reset` возвращает физическое состояние симулятора, но сохраняет историю, аварийную блокировку, cooldown и дневной расход, чтобы им нельзя было обходить защитные лимиты.

## Границы MVP

Насос, резервуар и GPIO симулируются. NASA GIBS даёт обзорный слой, а не анализ отдельных растений; числовой NDVI не заявлен. Погода зависит от доступности Open-Meteo и честно показывает `stale/unavailable`. Фоновая симуляция рассчитана на один API worker. В рабочей среде задайте HTTPS `WEB_ORIGIN`, уникальный пароль PostgreSQL и reverse proxy; подтверждение email, восстановление пароля, команды и роли организаций не входят в MVP.

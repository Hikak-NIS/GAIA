## Что проверяют тесты нового режима

- Сессия не выдаётся до подтверждения email; код одноразовый, истекает, ограничен пятью ошибками; повторная отправка имеет задержку и аннулирует старый код.
- При первой проверке email удаляются все сессии, созданные до введения подтверждения. Ошибка отправки не создаёт новый аккаунт с открытым доступом.
- Обычный пользователь не получает данные Global; после отзыва роли сохранённый URL и API тоже закрываются.
- Выключенный архивный режим не запускает виртуальный полив и не подмешивает старые сгенерированные показатели в рабочую историю.
- Реальные ответы сохраняют происхождение и даты; при отказе источников нет синтетической подстановки или утечки текста с секретом.
- Погодный ряд исключает будущие часы, отсутствующие значения остаются `null`; климатический CSV и NSIDC v4 правильно обрабатывают пропуски.
- Sentinel‑2: геометрия круга, предел радиуса, маски воды/суши, исключение полностью закрытых пикселей, доля валидных наблюдений.
- Помощник не читает чужой участок или закрытый анализ; контракты Responses, transcription и speech проверены с подменой сетевого вызова. Ключи не выдаются через настройки.
- Обучение модели, разделение по площадкам и времени, JSON-артефакт и выполнение проверены на изолированной тестовой выборке. Тестовая модель не установлена в рабочий каталог.

Код перехвата тестовой почты работает только со специально проверенными тестовой БД и origin, не входит в рабочий сервер.

## Исправление несовместимости работающего API и интерфейса

При повторной диагностике 10.11.2026 на порту 8000 обнаружен старый процесс API, запущенный 09.11.2026. Его OpenAPI не содержал `/api/v1/auth/verify-email` и маршрутов Earth. Новый интерфейс принимал старый ответ с пользователем за challenge и открывал форму кода, хотя старый сервер не отправлял письмо. Отдельная успешная SMTP-проверка этот случай не выявляла.

Старый API заменён текущим с существующей SQLite-базой; через `localhost:5173` подтверждена связь с новым API. Этот основной сервер оставлен работать вместо уже работавшего старого; тестовые порты освобождены. Интерфейс проверяет `verification_required`, `challenge_id`, `email_hint` перед показом формы. `dev.ps1` отклоняет занятые порты, ожидает API с поддержкой почты и завершает всё дерево Python-процессов. Последнее устраняет оставшийся дочерний интерпретатор Windows после остановки venv-запускателя. Проверены отказ при занятом порте и завершение отдельного дерева процессов.

Новый реальный вход владельца после этой замены ещё требует подтверждения самим владельцем; пароль не запрашивался и не изменялся.

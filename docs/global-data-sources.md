# Архив предыдущего этапа

Актуальные подключения и ограничения находятся в [описании реальных источников](earth-data-methods.md). Ниже сохранена историческая документация.

# Источники GAIA Global: подключение и ограничения

Обзор официальной документации выполнен 8 ноября 2026. Численные данные сейчас создаёт только явно обозначенный DEMO-провайдер. Ниже — план подключения, а не заявление о работающих интеграциях.

## Copernicus Data Space / Sentinel-2

STAC-каталог предназначен для поиска продуктов по пространственным и временным условиям. Точка подключения в адаптере: `https://stac.dataspace.copernicus.eu/v1`. После поиска следует выбрать подходящий сервис загрузки/обработки и его способ авторизации; регистрацию пользователя и квоты учитывать отдельно от поиска метаданных. См. [STAC API](https://documentation.dataspace.copernicus.eu/APIs/STAC.html) и [квоты](https://documentation.dataspace.copernicus.eu/Quotas.html).

Условия доступа к данным Sentinel и материалам портала различаются: свободный доступ к Sentinel регулируется отдельным Legal Notice; другие материалы сайта не следует автоматически считать свободными для перепубликации. Перед подключением проверить применимые условия продукта и атрибуцию. [Условия CDSE](https://dataspace.copernicus.eu/terms-and-conditions).

План: каталог → выбор L2A-сцен → cloud/quality mask → расчёт индекса по NIR/red → статистика выбранной геометрии → сохранение provenance. Формула NDVI `(NIR − red)/(NIR + red)` описана в [официальном руководстве Earth Engine](https://developers.google.com/earth-engine/tutorials/tutorial_api_06). Выбор каналов, масштабирование reflectance и маски надо подтвердить для конкретного продукта перед реализацией. Облачность и отсутствие валидных пикселей должны давать `unavailable`, а не нулевой NDVI.

## NASA Earthdata

CMR Search предоставляет поиск коллекций и гранул; в модуле задан `https://cmr.earthdata.nasa.gov/search/granules.json`. Реальная интеграция должна выбрать версии коллекций для LST, осадков и влажности, проверить пространственное/временное покрытие и QA. [CMR Search API](https://cmr.earthdata.nasa.gov/search/site/docs/search/api.html).

Для защищённых загрузок нужен Earthdata Login и авторизация, соответствующая сервису; секреты хранятся только на сервере, не в frontend. [Earthdata Login: доступ к данным](https://urs.earthdata.nasa.gov/documentation/for_users/data_access/curl_and_wget).

GIBS выдаёт заранее подготовленные визуализации, организованные в тайловую пирамиду. Подключённая в интерфейсе подложка служит визуальному ориентированию; извлекать из цвета тайла численный LST/NDVI нельзя. [GIBS API](https://nasa-gibs.github.io/gibs-api-docs/).

План: CMR → product/granule metadata → авторизованная загрузка при необходимости → quality filtering → приведение единиц и временного окна → spatial aggregation. LST не подменять температурой воздуха, а объёмную влажность SMAP — относительным процентом с садового сенсора. Условия и атрибуцию проверять для выбранной коллекции.

## Google Earth Engine

Доступ требует Cloud project с включённым Earth Engine API, регистрацией commercial/noncommercial и соответствующими ролями. Для некоммерческого использования требуется подтверждение eligibility; коммерческому использованию нужен соответствующий платный план. Авторизация и billing не возникают автоматически от установки библиотеки. [Доступ к Earth Engine](https://developers.google.com/earth-engine/guides/access), [коммерческое использование](https://developers.google.com/earth-engine/guides/transition_to_commercial).

План: проект и серверная авторизация → проверяемые вычислительные задания → облачные композиты/агрегации → сохранённые результаты. Учесть квоты, асинхронные задачи и стоимость; не запускать дорогостоящие вычисления от каждого pan/zoom карты. Интеграция пока выключена и возвращает явную недоступность.

## Общий контракт качества

Реальный адаптер должен возвращать геометрию и CRS, единицы, источник и версию продукта, время измерения и загрузки, разрешение, качество/долю валидных пикселей и используемую норму. Даты обновления — не доказательство свежести наблюдения. Ошибки авторизации, квот, сети или качества не должны превращаться в незаметную генерацию DEMO.

GEHI v0.1 сейчас использует демонстрационные климатические ориентиры. Подключение реальных наблюдений требует отдельной версии модели и её проверки по биомам/сезонам, прежде чем выводы можно будет интерпретировать как оценку реальной деградации.

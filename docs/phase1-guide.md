# Как работать с GAIA после Phase 1

## Запуск

Из PowerShell в `D:\GAIA`:

```powershell
.\scripts\dev.ps1 -UseSqlite
```

Откройте [GAIA](http://localhost:5173). API-документация доступна на [localhost:8000/docs](http://localhost:8000/docs). Используйте `localhost`, соответствующий WEB_ORIGIN. Для остановки нажмите Ctrl+C в терминале запуска. Данные сохраняются в `data/gaia.db`, фотографии — в `data/uploads`; не удаляйте эти файлы для обычного перезапуска.

Docker Compose использует PostgreSQL; команды и переменные приведены в корневом README. Сначала скопируйте `.env.example` в `.env` только если `.env` ещё не существует.

## Первый рабочий сценарий

1. Зарегистрируйтесь или войдите в существующий аккаунт.
2. Откройте **Профили растений** в боковом меню. Создайте профиль: название культуры, известные диапазоны, требования к свету/поливу/питанию. Диапазон заполняйте обеими границами; неизвестный оставляйте пустым. В раскрывающемся разделе можно задать особые требования стадии роста.
3. Создайте территорию или откройте существующую. Во вкладке **Зоны** уже есть основная зона. Добавляйте отдельные зоны для грядок, теплицы и других мест выращивания.
4. Во вкладке **Растения** нажмите «Добавить растение». Выберите профиль и зону, укажите имя экземпляра, дату посадки и стадию.
5. Выберите сенсорные каналы, которые действительно относятся к этому растению. Для демонстрации можно привязать каналы виртуальной станции основной зоны.
6. Откройте карточку растения: здесь видны требования текущей стадии, последние измерения выбранных сенсоров и их история. REAL и SIMULATED подписаны отдельно. Health Score ещё не рассчитывается.

Изменение профиля и стадии меняет отображаемые требования растения. Настройки существующего виртуального полива пока сохраняются отдельно во вкладке **Полив**.

## Проверка симулятора

Откройте **Симуляция**, выберите «Засуха», скорость ×60 и «Запустить». Во вкладке **Полив** включите автоматический режим с порогом 30% и целью 45%. Насос запускается после пересечения порога и останавливается по цели либо ограничению безопасности. Записи содержат причину, длительность и расчётный расход.

Обзор, показатели, предупреждения, полив и новые ежедневные отчёты относятся к этому симулятору. Старые сохранённые отчёты не пересчитываются. Основная зона имеет один симулятор; создание дополнительных зон не создаёт новые виртуальные насосы.

## Реальная телеметрия

1. В **Устройствах** нажмите «Добавить устройство». Выберите зону и тип «Сенсорная станция». Новая карточка имеет источник REAL и статус OFFLINE до первого пакета.
2. В карточке выберите «Выдать / сменить ключ». Сохраните Sensor ID и ключ: он показывается один раз. Новый ключ отзывает старый.
3. Клиент устройства отправляет HTTP POST на `/api/v1/devices/telemetry`, с `Authorization: Bearer <ключ>` и JSON:

```json
{
  "sensor_id": "ID из карточки устройства",
  "timestamp": "текущее время ISO 8601 с часовым поясом",
  "source": "device",
  "soil_moisture_pct": 41.2,
  "air_temperature_c": 23.0,
  "air_humidity_pct": 62.0,
  "light_lux": 1200,
  "quality": "valid"
}
```

Текстовые подсказки в примере замените настоящими значениями. Время должно находиться в пределах пяти минут от времени сервера и строго возрастать для этой станции. API возвращает 401 для неверного/отозванного ключа, 422 для неверного payload и 409 для повторной либо более старой записи.

После пакета обновляются каналы и last_seen. Через 120 секунд без новых пакетов станция становится OFFLINE. Исходное качество измерения и его текущая свежесть отображаются отдельно. Несколько станций имеют независимые ключи и историю.

Камеру или привод можно зарегистрировать как объект реестра, но heartbeat, захват изображений, GPIO и команды пока не подключены. REAL телеметрия не управляет виртуальным насосом. Пример в `devices/raspberry_pi/client.py` отправляет тестовые значения из окружения; он не является драйвером физических сенсоров.

## Изменение и удаление

- Профиль можно изменить; удалить — только если им не пользуются растения.
- Основная зона защищена. Дополнительная зона удаляется, когда не содержит растений и устройств.
- Устройство деактивируется через «Настроить» → снять «Устройство активно». Ключ отзывается, показания сохраняются. После повторной активации выдайте новый ключ.
- Устройство с историей или привязками нельзя переносить в другую зону. Для другого места измерения зарегистрируйте отдельное устройство.
- Удаление растения сохраняет историю сенсоров. Удаление всей территории удаляет её данные и требует подтверждения в интерфейсе.
- Калибровка в Phase 1 хранит метаданные. Готовые физические значения должен отправлять клиент; сервер не пересчитывает прежние измерения.

## Структура для разработки

`apps/api/gaia/main.py` — запуск, middleware и фоновые задачи; `api/routes/` — маршруты; `services/foundation.py` — новая предметная логика; `domain.py` — существующий симулятор и полив; `foundation_models.py` — новые модели; `apps/web/src/foundation/` — новые страницы.

Проверки: `scripts/check.ps1`, затем `npm run test:e2e` из `apps/web`. Backend-тесты используют временные базы; E2E — отдельную `data/gaia_e2e.db` и порты 8001/5174. Не запускайте E2E против рабочей базы. Изменения схемы добавляйте новой ревизией Alembic; применённые миграции не переписывайте.

Дальнейшие фазы и границы ответственности описаны в [архитектурном плане](phase1-plan.md).

## Данные и доступ

`User` получает `nickname`, уникальный регистронезависимый `nickname_key`, `role` с DB check constraint. Частичный unique index допускает не более одного `superadmin`. Главный администратор назначается миграцией только существующему аккаунту `gulnarapulatova9@gmail.com`; ник становится `SENQwir`. Регистрация не повышает права и запрещает зарезервированный email/ник, включая на пустой БД. На новом развёртывании требуется отдельное доверенное первоначальное создание владельца, а не публичная саморегистрация под этим адресом.

Каждый API Global вызывает `admin_user`, каждое управление ролями/весами — `superadmin_user`. Роль читается из БД на каждом запросе, не из cookie, client state или email. Cookie хранит случайный токен, в БД — только его хеш. Снятие роли блокирует Global даже для уже открытой сессии. Публичное тело регистрации не принимает `role`; тело изменения роли принимает только `user`/`admin`. Чужие личные территории не становятся доступны администратору через эту роль.

`GlobalAnalysis` хранит неизменяемый JSON snapshot результата: область, источник, сценарий, даты, показатели, история, факторы, версия GEHI/весов, рекомендации. Анализы и маркеры общие для администраторов. `GlobalMarker` хранит автора, координаты и ручную заметку. Удалить его может автор или главный администратор. `GlobalSettings` содержит веса и optimistic revision; устаревшее изменение возвращает 409. `AdminAudit` фиксирует изменения ролей и весов.

Миграция добавляет таблицы и поля, не сбрасывает пароли, сессии или историю. SQLite rebuild таблицы `users` использует существующий миграционный transaction/FK-check, чтобы избежать каскадного удаления дочерних данных. Downgrade с потерей истории запрещён; используйте backup. Утилита обновления сравнивает все прежние колонки, допуская добавление новых.

## Контракт провайдера

`EnvironmentalProvider.describe()` возвращает честный статус и требования подключения. `fetch(area, scenario, as_of)` возвращает нормализованные значения с источником, временем, базовыми значениями и историей либо явную ошибку `ProviderUnavailable`. Только DemoProvider сейчас реализует извлечение (генерацию) значений. PlannedProvider никогда не возвращает вымышленные реальные измерения.

Будущая обработка реальных данных должна добавить product ID, геометрию, разрешение, время измерения/получения, QA/cloud mask, valid pixel fraction, единицы, статистику площади и происхождение климатической нормы. Для реального продукта потребуется отдельная версия нормировки GEHI: нельзя просто подставить реальные пиксели в демонстрационные пороги.

## GEHI-concept-0.1

`clamp(x)` ограничивает результат 0–100. Базовые веса: 25/25/15/20/15%, сумма строго 100. Веса редактируются только главным администратором; все изменения журналируются.

| Фактор | Формула для DEMO | Вес |
|---|---|---:|
| Растительность | `clamp(NDVI / 0.8 × 100)` | 25% |
| Влажность | `clamp(soil_moisture / 45 × 100)` | 25% |
| Температура | `clamp(100 − abs(LST − 24) × 10)` | 15% |
| Динамика покрова | `clamp(70 + change_pp × 3)` | 20% |
| Осадки | `clamp(rain_mm_30d / 60 × 100)` | 15% |

GEHI = округлённая сумма `factor_score × weight / 100`. Отображаемая условная деградация `100 − GEHI` является производной, не независимым наблюдением. Каждый фактор показывает вклад, вес, формулу и фактический DEMO-вход. История содержит 12 месячных точек; изменение покрытия — разность крайних значений в процентных пунктах. Это демонстрационное 12-точечное окно, не точное измерение годовой разницы по снимкам.

Рекомендации формируются независимыми прозрачными правилами: разреженная растительность → обследование и местные виды/эрозия; недостаток влаги → водный баланс/удержание; температурная аномалия → микроклимат; убыль покрова → исследование причин; рост → проверка устойчивости восстановления. Биоразнообразие не выводится из NDVI; предлагается полевой учёт.

## API

Все пути под `/api/v1`; изменения требуют CSRF-заголовок `X-GAIA-Request: 1` и допустимый Origin.

| Метод и путь | Доступ | Результат |
|---|---|---|
| POST `/auth/register` | публичный | имя, обязательный ник, email, пароль; роль user |
| POST `/auth/login` | публичный | `identifier` (ник/email), пароль; прежнее поле email поддержано |
| PUT `/users/me/nickname` | свой аккаунт | смена уникального ника; ник главного защищён |
| GET `/global/providers` | admin+ | статусы и требования источников |
| GET `/global/settings` | admin+ | веса и ревизия |
| PUT `/global/settings` | superadmin | веса с суммой 100, expected_revision |
| POST `/global/analyses` | admin+ | area, source, scenario → сохраняемый анализ |
| GET `/global/analyses` | admin+ | последние результаты, limit 1–100 |
| GET `/global/analyses/{id}` | admin+ | полный snapshot |
| GET/POST `/global/markers` | admin+ | последние 200 / ручной маркер |
| DELETE `/global/markers/{id}` | автор-admin либо superadmin | удалить маркер |
| GET `/admin/users` | superadmin | q, page, administrators_only; 25 аккаунтов на страницу |
| PUT `/admin/users/{id}/role` | superadmin | user/admin; главный защищён |
| GET `/admin/audit` | superadmin | последние 100 изменений |

Ответы: 401 — нет сессии; 403 — нет роли; 404 — объект не найден; 409 — конфликт/защищённая роль/устаревшие веса; 422 — неверные данные; 503 — реальный провайдер ещё не подключён. Старые маршруты и user/device авторизация сохраняются.

## Границы MVP

Нет численного спутникового ingestion, polygon editor, региональной научной валидации, прогнозов и автоматического экологического вмешательства. GIBS — визуальная подложка. Полная Earth Engine интеграция, сравнение территорий и автоматизированный мониторинг показаны в roadmap как будущие возможности, без неработающих кнопок. Система по-прежнему требует один API worker из-за существующего фонового симулятора.
